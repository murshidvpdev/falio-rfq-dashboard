# Free Deployment Guide

Stack: **Render** (backend, free web service) + **Neon** (free Postgres) + **Vercel** (frontend, static).

## 1. Database — Neon

1. Sign up at https://neon.tech and create a project/database.
2. Copy the connection string. It looks like:
   ```
   postgresql://<user>:<password>@<host>/<db>?sslmode=require
   ```
3. Convert it for SQLAlchemy async by adding `+asyncpg` after `postgresql`:
   ```
   postgresql+asyncpg://<user>:<password>@<host>/<db>
   ```
   (drop `?sslmode=require` — asyncpg needs `?ssl=require` instead, or omit and let Neon's default pooler handle it. If you hit SSL errors, use `?ssl=require`.)

## 2. Backend — Render

1. Push this repo to GitHub (already done).
2. In Render: **New > Blueprint**, select this repo. It will read [render.yaml](render.yaml).
3. Fill in the prompted env vars:
   - `DATABASE_URL` — the Neon connection string from step 1
   - `ALLOWED_ORIGINS` — your Vercel frontend URL once you have it (e.g. `https://rfq-dashboard.vercel.app`). You can leave as `*` initially and tighten later.
4. `SECRET_KEY` is auto-generated by Render.
5. On first deploy, the container runs `alembic upgrade head` then `python seed_rbac.py` automatically (see `Dockerfile.backend` CMD), then starts uvicorn. The seed script is idempotent — it creates the RBAC roles/permissions and a default super admin user (`superadmin` / `Admin@1234!`) only if they don't already exist, so it's safe to run on every deploy. No paid Shell access is needed.
6. Note your backend URL, e.g. `https://rfq-dashboard-backend.onrender.com`.
7. Log in to the deployed frontend with `superadmin` / `Admin@1234!` and **change the password immediately** from the Users page.

**Note:** Render's free tier has an ephemeral filesystem — files written to `backend/files/` (the automation feature) do **not** persist across restarts/deploys.

## 3. Frontend — Vercel

1. In Vercel: **New Project**, import this repo.
2. Set **Root Directory** to `frontend`.
3. Framework preset: Vite (auto-detected). Build command `npm run build`, output `dist`.
4. Add environment variables:
   - `VITE_API_BASE_URL` = `https://rfq-dashboard-backend.onrender.com`
   - `VITE_WS_BASE_URL` = `wss://rfq-dashboard-backend.onrender.com`
5. Deploy. Note your frontend URL, e.g. `https://rfq-dashboard.vercel.app`.
6. Go back to Render and set `ALLOWED_ORIGINS` to this URL, then redeploy the backend.

## 4. Verify

1. Open the Vercel URL, register a user, log in.
2. Visit `/dashboard` — the WebSocket should connect to the Render backend (check browser dev tools Network tab for `wss://...`).

## Limitations of the free tiers

- **Render free web service** spins down after ~15 min idle; first request after that takes 30-60s (cold start) and drops any open WebSocket.
- **Neon free Postgres** has a generous always-free tier but with compute auto-suspend after inactivity (a few seconds of cold start on first query — much shorter than Render's).
- **File automation** (`backend/files/source` etc.) won't persist on Render's free tier — fine for demoing the dashboard, not for production file processing.
